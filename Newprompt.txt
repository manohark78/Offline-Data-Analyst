Build a local request tracker as two files: tracker.html and run.ps1. Target: Windows, no admin rights, no internet, no external libraries or CDN.

run.ps1
- Read the current Windows user with $env:USERNAME.
- Start a local server using System.Net.HttpListener on http://localhost:8080/ (pick a free port if busy).
- Serve tracker.html from the same folder.
- API endpoints:
  GET /api/user -> returns {"username": "<$env:USERNAME>"}
  GET /api/requests -> returns all requests from tracker.json
  POST /api/requests -> saves the full list to tracker.json (write atomically, create the file if missing)
- Open the page in the default browser automatically.
- Handle errors cleanly and print the URL in the console.

tracker.html (single file, inline CSS and JS, clean modern UI)
- Fetch the username from /api/user and show it in the header. If the API is unavailable (file opened directly), fall back to asking for a name once and remember it in localStorage.
- Request form fields:
  Type: dropdown (VA / PT / Others)
  Title: text, max 200 chars, with live character counter
  Description: textarea, max 1000 chars, with live character counter
  Status: dropdown (Open / In progress / Closed), default Open
- On save, each request gets an auto ID (e.g. REQ-001), created date-time, and created-by username (from the API, not editable).
- Request list view: table with ID, Type, Title, Status, Created by, Created at. Search box, filter by Type and Status. Status shown as a colored badge. Click a row to open details.
- Detail view: edit Type/Title/Description/Status (Status change allowed anytime), and a Comments section:
  - Add comment: max 200 chars with live counter, limit of 15 comments per request (show a message when the limit is reached).
  - Each comment is saved with date-time and username automatically.
  - Display comments as: [DD/MM/YYYY HH:mm] USERNAME: comment text
- Print button on the detail view: print-friendly layout (hide buttons and sidebar via @media print) showing request ID, Type, Title, Status, Description, created by/at, and all comments with their date-time and username.
- Export all requests to CSV.
- Escape all user input to prevent HTML injection.
- Persist everything through the API (tracker.json), not only in the browser.

---java

Build a local request tracker as a Java backend plus a single HTML page. Target: Windows, no admin rights, no internet, no external libraries or CDN. Use only the JDK (Java 17 or lower compatible), com.sun.net.httpserver.HttpServer, no Spring, no Maven dependencies. Write a small JSON reader/writer by hand, or use simple string-based JSON handling, so no library is needed.

Project structure
- Tracker.java (single file with main, can contain small static helper classes)
- web/index.html (single file, inline CSS and JS)
- data/ folder (created automatically if missing)
- run.bat (compiles if needed and runs: javac Tracker.java && java Tracker)

Usage context
- The folder is shared on OneDrive with multiple users. Each user runs the app on their own machine, and all of them read/write the same data/ folder.
- Therefore: never keep all requests in a single file. One request = one JSON file, to avoid overwrite conflicts.

Backend (Tracker.java)
- Start HttpServer on http://localhost:8080/ (try next ports if busy), open the browser automatically with Desktop.browse.
- Username comes from System.getProperty("user.name"). Never accept a username from the client.
- Serve web/index.html at "/".
- API endpoints (all return JSON, with proper error codes and messages):
  GET  /api/user -> {"username": "..."}
  GET  /api/requests -> list of all requests (read every file in data/requests/)
  POST /api/requests -> create a new request
  PUT  /api/requests/{id} -> update Type, Title, Description, Status of an existing request
  GET  /api/comments?requestId=... -> comments of that request, sorted oldest to newest
  POST /api/comments -> add a comment to a request
- Request fields and validation (validate on the server, not only in the page):
  type: VA / PT / Others
  title: required, max 200 chars
  description: max 1000 chars
  status: Open / In progress / Closed (default Open)
  id: unique, format REQ-yyyyMMdd-HHmmss-USERNAME (no sequential numbers)
  createdBy: username (set by server), createdAt: ISO datetime (set by server)
- Storage:
  data/requests/<id>.json (one file per request)
  data/comments/<id>/<yyyyMMdd-HHmmss-SSS>-<username>.json (one file per comment)
- Writing files: write to a temp file first, then move it atomically, so a half-written file never appears.
- When updating a request, re-read the latest file from disk before writing.

Comments rules
- Max 15 comments per request. Before saving, re-count existing comment files on disk and reject with a clear message if the limit is reached.
- Max 200 characters per comment.
- Append-only: no edit and no delete.
- Date-time is generated by the server at save time (local time), username by the server.
- Comment file content: {"requestId": "...", "user": "...", "createdAt": "ISO datetime", "text": "..."}

Frontend (web/index.html)
- Keep the JavaScript minimal, simple (plain fetch, no frameworks) and well commented, since the developer is not strong in JS. Each function should have a one-line comment explaining what it does.
- Show the username in the header (from /api/user).
- Form: Type dropdown, Title (live counter /200), Description textarea (live counter /1000), Status dropdown.
- List view: table with ID, Type, Title, Status, Created by, Created at. Search box, filter by Type and Status, colored status badge. Click a row to open the detail view.
- Detail view: edit fields, change status, comments section with a text box (live counter /200), and "Comment limit reached" message when 15 comments are done (disable the Add button).
- Comments display format: [DD/MM/YYYY HH:mm] USERNAME: comment text
- Auto refresh the list and comments every 15-20 seconds, plus a Refresh button.
- Print button on the detail view: print-friendly layout (@media print hides buttons) showing request ID, Type, Title, Status, Description, created by/at, and all comments in the same format.
- Export all requests to CSV.
- Escape all user text before putting it into the page, to prevent HTML injection.

Deliverables
- Complete working code for Tracker.java, web/index.html and run.bat.
- Short run instructions, plus a list of all API endpoints with example request/response.
- Comment the Java code clearly, explaining each endpoint handler.
